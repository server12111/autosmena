# SMENA

Telegram-магазин аренды номеров на api.cc с балансом в USD, веб-админкой и пополнениями через TON Center, Crypto Pay и xRocket.

## Текущее состояние

Работают локальные демосценарии: каталог → пополнение → покупка → SMS / отмена с возвратом. Адаптер api.cc написан по `docs/apicc.openapi.json`; с аккаунтом проверено чтение профиля, категорий и части каталога. Платные методы и платёжные клиенты требуют контрольной проверки с вашими ключами. Не включайте продажи до сверки валюты поставщика, каталога, срока продления и контрольного заказа.

- Первичная аренда и повторное использование: `POST /api/v1/buy/create`, по одному номеру.
- Покупаются только номера из пункта «Більше 60 днів»: `expiry=5` (в OpenAPI — 60–80 дней остатка). Перед покупкой наличие проверяется через `/api/v1/buy/prefix` с тем же фильтром; при включении товара в админке проверка тоже обязательна. Пункт «больше 80 дней» с доплатой не используется.
- Продление своего номера: `POST /api/v1/order/renewApis`, стандартный срок поставщика. Разные месячные пакеты пока не реализованы.
- SMS: бот выдаёт персональную ссылку приёма и уведомляет об увеличении `sms_count`. Текст SMS напрямую в боте требует образца ответа `/api/record`, которого в OpenAPI нет. В деморежиме код приходит прямо в бот.
- Автоотмены реальной аренды нет: такого метода нет в полученной документации. В админке можно разобрать неопределённую покупку и привязать фактический заказ либо вернуть внутренний баланс после проверки отсутствия списания / возврата у поставщика.
- Проверка списков номеров, отложенная выдача, выбор префиксов и смена токена приёма пока не включены в интерфейс.
- Валюта внутреннего учёта сейчас USD. Для каждого товара можно выбрать процентную наценку или фиксированную цену.
- Отчёт исправленных ошибок и границы проверки: [docs/REVIEW.md](docs/REVIEW.md).

## Локальный запуск (Windows PowerShell)

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.lock
.venv/Scripts/python.exe -m pip install -e '.[dev]'
Copy-Item .env.example .env  # только если .env ещё не существует
.venv/Scripts/python.exe -m app.cli password
```

Скопируйте выведенную строку `ADMIN_PASSWORD_HASH=...` в `.env`. Это хеш, исходный пароль не сохраняется. Оставьте `DEMO_MODE=true` для демонстрации; все реальные платёжные ключи в этом режиме игнорируются. Добавьте `BOT_TOKEN`, чтобы проверить интерфейс в Telegram.

```powershell
.venv/Scripts/python.exe -m alembic upgrade head
.venv/Scripts/python.exe -m app.cli seed
.venv/Scripts/python.exe -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Админка: <http://127.0.0.1:8000>. В двух отдельных терминалах:

```powershell
.venv/Scripts/python.exe -m app.bot
.venv/Scripts/python.exe -m app.worker
```

В боте нажмите `/start` → «Баланс» → `demo`. Созданный счёт подтвердите в админке в разделе «Пополнения». Купите тестовый номер: через 45 секунд worker отправит тестовый код. До получения кода можно отменить демозаказ и проверить возврат.

## Подключение api.cc

В `.env` задайте `APICC_API_KEY` и `APICC_USD_RATE` — сколько USD стоит одна единица валюты кабинета api.cc. Если цены действительно в USD, значение `1`. Для другой валюты нужен подтверждённый курс. Документация валюту не указывает, поэтому приложение не подставляет её самостоятельно.

После отключения деморежима: «Каталог и цены» → «Импорт из api.cc» → «Показать категории api.cc». Укажите ID категории и её русское название. Импортируются типы `1` (первичный), `2` (повторный) и `3` (продление). Новые товары выключены: проверьте их стоимость, настройте цену и включите нужные. Тип продления отображается в редактировании товара, а покупателю предлагается через «Мои заказы» → «Продлить номер».

Перед реальной покупкой бот ещё раз проверяет цену поставщика. Если она изменилась, заказ получает возврат до обращения к платному методу, а каталог нужно обновить. Между проверкой цены и покупкой API поставщика не позволяет атомарно закрепить закупочную цену — этот риск остаётся.

## Платежи

**Crypto Pay:** `CRYPTOPAY_TOKEN` и `CRYPTOPAY_URL`. Для mainnet: `https://pay.crypt.bot/api`. Счёт номинирован в USD, принимаются TON и USDT. Статус проверяется через `getInvoices`. Необязательный webhook: `POST https://ваш-домен/webhooks/cryptopay`; проверяется подпись исходного тела, затем статус дополнительно запрашивается у провайдера. Без домена работает polling.

**xRocket:** `XROCKET_TOKEN`, `XROCKET_URL=https://pay.xrocket.tg`. Реализован документированный Legacy API с заголовком `Rocket-Pay-Key`; используйте ключ Legacy. Новый Pay API требует других учётных данных и в этом проекте пока не реализован. Счёт в USDT, зачисление в USD 1:1 без дополнительной комиссии магазина; комиссии провайдера несёт магазин. Проверка через REST, webhook не требуется.

**Прямой TON:** `TONCENTER_API_KEY`, `TONCENTER_URL`, `TON_WALLET`, `TON_TESTNET`. Для mainnet: `https://toncenter.com/api/v3`, `TON_TESTNET=false`. Курс TON/USD берётся из Crypto Pay `getExchangeRates`, поэтому также нужен `CRYPTOPAY_TOKEN`. Сумма округляется вверх до nanoTON и фиксируется на время счёта. Проверяются комментарий, адрес, сумма, время, отсутствие bounce/aborted и включение транзакции минимум в предыдущий masterchain-блок. Один hash нельзя зачислить дважды. Seed-фраза кошелька не нужна.

Просроченные счета ещё сверяются в течение 30 дней; TON принимается автоматически только если транзакция прошла в интервале действия счёта. Поздние переводы, переводы без комментария и недоплаты требуют ручной сверки. Переплата зачисляет только заявленную сумму счёта. Автовывод средств не реализован.

Тестовые платежи и реальные покупки api.cc должны запускаться в разных окружениях и базах. Приложение запрещает комбинацию testnet-платежей с ключом реального поставщика вне деморежима.

## Сервер и PostgreSQL

Для самостоятельной установки есть [пошаговая инструкция](deploy/INSTALL.md), мастер конфигурации и скрипты запуска / обновления:

```sh
python3 deploy/setup.py
nano .env
bash deploy/manage.sh start
```

Мастер работает без сторонних Python-пакетов, не перезаписывает `.env` и генерирует пароль PostgreSQL. Без домена используется SSH-туннель с явным режимом `ADMIN_ACCESS_MODE=ssh_tunnel`. Для домена добавляется Caddy с HTTPS. Сборка архива без локальных ключей и баз: `python deploy/package.py`.

## Учёт и ограничения

- Деньги хранятся целыми числами в миллионных долях USD. Операции журнала и баланс меняются в одной транзакции. Списание условное: баланс не может стать отрицательным.
- Цена и себестоимость фиксируются в заказе. Повторное подтверждение использует тот же ключ заказа.
- При таймауте платной операции нет автоматической повторной покупки или возврата. Заказ переходит в `review`; после падения процесса зависшая покупка тоже переводится на сверку.
- Уведомления сохраняются в БД до отправки. При падении между отправкой сообщения и фиксацией доставки возможно повторное уведомление; повторного списания из-за этого нет.
- Админка: один администратор, пароль scrypt, HttpOnly/SameSite cookie на 8 часов, CSRF, аудит изменений. Ограничитель попыток входа хранится в памяти; запускайте один процесс админки, а при публичном доступе добавьте ограничитель на reverse proxy.
- SQLite предназначен для демо. Production требует PostgreSQL. Сами PostgreSQL и Docker в текущем окружении не запускались.
- Бот и worker должны работать в одном экземпляре каждый. FSM ввода суммы и подтверждения продления хранится в памяти: после перезапуска ввод нужно повторить; финансовые операции сохраняются в БД.
- Реализованные интеграции требуют контрольной проверки с вашими аккаунтами. Автоматизированные тесты используют локальную БД и имитации ответов провайдеров.
