# SMENA

Telegram-магазин номеров api.cc: баланс в USD, админка, TON, Crypto Pay и xRocket.

## Bothost: минимум настроек

Выберите Dockerfile из репозитория. Он запускает `python main.py`: программа создаёт/обновляет базу и запускает бота, админку и проверку платежей в одном контейнере.

В `.env.example` остались только:

- `BOT_TOKEN` — Bothost обычно передаёт его автоматически.
- `APICC_API_KEY` — ключ поставщика номеров.
- `CRYPTOPAY_TOKEN` — Crypto Pay и курс TON/USD.
- `XROCKET_TOKEN` — ключ Legacy API xRocket.
- `TONCENTER_API_KEY` — проверка прямых переводов TON.
- `TON_WALLET` — адрес кошелька.

Ненужные способы оплаты оставьте без ключей. Переменные базы, URL API, портов, пароля PostgreSQL и курса добавлять не нужно. Mainnet-адреса API заданы в коде. На хостинге тестовые номера отключены: без ключа api.cc покупки недоступны. Локальный деморежим требует явного `DEMO_MODE=true`.

SQLite находится в `/app/data/smena.db`. Включены WAL, `synchronous=FULL`, внешний ключевой контроль и атомарное изменение баланса с журналом. Папка создаётся автоматически, миграции применяются до запуска служб. Старая `smena.db` из корня переносится через SQLite backup API, включая WAL; исходник сохраняется. Рабочая база в постоянной папке не перезаписывается.

Первый пароль админки создаётся автоматически и сохраняется между перезапусками. Посмотреть в терминале хостинга:

```sh
cat /app/data/admin-access.txt
```

Откройте HTTPS-домен, выданный хостингом. Веб-сервер слушает `0.0.0.0`, порт берёт из уже существующего `PORT` платформы либо использует 8000. В админке: «Каталог и цены» → «Валюта поставщика» → фактическая валюта кабинета api.cc → импорт → настройка цен → включение товаров. Изменение курса отключает товары до проверки новых цен.

В поле Bothost «Порт веб-приложения» укажите **8000**. Каталог теперь содержит только виртуальный проект Telegram США с закупочной ценой $0.30 (`cate_id=2`, `app_id=74`); физические номера, другие сервисы и страны запрещены также на серверной стороне. Команда `/catalog` сразу открывает номера; `/search` сохранена как совместимый переход в тот же каталог.

Бот работает «одним экраном»: навигация редактирует текущее сообщение, а не шлёт новые. Флоу покупки: Купить номер → карточка с ценой и балансом (если денег не хватает — сразу кнопка «Пополнить») → «Получаем номер…» → карточка номера с кнопками копирования номера/кода. Отмены заказа в боте нет. Код из SMS приходит отдельным сообщением с кнопкой «Скопировать код». Пополнение: способ → быстрые суммы $1–$50 или своя сумма сообщением. Любой текст вне диалога открывает меню.

**Профиль.** В меню «Профиль»: баланс, активные номера, траты, «Мои номера», рефералы и API. В карточке номера после первого кода появляется «Получить код ещё раз»: у поставщика нет метода повторной отправки, код снова запрашивается в самом Telegram, а бот ловит каждый новый код, пока аренда активна.

**Рефералы.** Ссылка `https://t.me/<бот>?start=ref_<ID>`. Пригласивший получает 5% (`REFERRAL_PERCENT`) с каждого пополнения приглашённого, сразу на баланс, с уведомлением; один раз на платёж. Реферер закрепляется только за новым пользователем, себя пригласить нельзя.

**API для реселлеров.** Ключ создаётся в боте: Профиль → API (показывается один раз, хранится только хеш; перевыпуск отключает старый). Базовый адрес — домен из админки «Вебхуки» или `PUBLIC_URL` (по умолчанию домен Bothost). Заголовок `Authorization: Bearer smn_…` (или `X-API-Key`), лимит 60 запросов в минуту, оплата с баланса пользователя по ценам магазина.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/reseller/v1/balance` | баланс |
| GET | `/reseller/v1/products` | товары и цены |
| POST | `/reseller/v1/orders` | купить: `{"product_id": 1, "request_id": "ваш-id"}`; повтор `request_id` вернёт тот же заказ |
| GET | `/reseller/v1/orders` | история (`?offset=`) |
| GET | `/reseller/v1/orders/{id}` | статус, номер, `code`, срок |

**Баннеры разделов.** Экраны с картинкой отправляются фото с подписью: картинка и текст приходят вместе. Каждая картинка загружается в Telegram один раз, дальше бот переиспользует сохранённую копию, поэтому экраны открываются мгновенно. Файлы — `app/static/brand/`: `main` (меню), `buy` (каталог), `numbers` («Мои номера»), `profile`, `wallet`, `ref`, `api`. Чтобы заменить картинку, положите PNG 1280×720 с тем же именем: бот заметит изменение файла и загрузит новую. Профиль и кошелёк рисуются с данными пользователя (база — `app/static/brand/base/`). Домен для картинок не нужен. Исходники баннеров — `docs/brand/`.

**Обязательная подписка.** Админка в боте → «Обязательная подписка» → «Добавить канал» (@username, ссылка t.me/… или ID `-100…`). Бот должен быть администратором канала — иначе Telegram не показывает подписчиков, и бот не даст добавить такой канал. Пока пользователь не подписан, вместо магазина он видит кнопки каналов и «Я подписался»; реферальная ссылка при этом сохраняется. Админы проверку не проходят. Если бот потерял доступ к каналу, проверка этого канала пропускается, чтобы не закрыть магазин для всех.

**Админка в боте.** Кнопка «Админка» в меню и команда `/admin` видны только ID из `ADMIN_IDS` (по умолчанию `7145919720`, несколько ID — через запятую). Там: статистика (пользователи, пополнения, продажи, выручка, маржа), включение/выключение товаров, цена в $ или наценка в %, поиск пользователя по ID или @username, начисление/списание баланса (с уведомлением клиенту), блокировка, заказы «на проверке» с возвратом денег после сверки. Все действия пишутся в аудит. Веб-админка остаётся для импорта каталога и настроек.

Цвета кнопок: синий — покупка, зелёный — оплата/подтверждение, красный — отмена; навигация нейтральная. Все иконки кнопок и текстов подобраны из набора premium-эмодзи, который Telegram даёт ботам (forum topic icons), поэтому premium-версия есть у каждой. Если Telegram отклоняет premium-разметку, сообщение повторяется с обычными иконками.

## Номера и платежи

- Новая аренда и повторное использование: только «Більше 60 днів», `expiry=5` (в OpenAPI — 60–80 дней). Наличие проверяется с тем же фильтром перед покупкой и при включении товара.
- Продление существующего номера: стандартные месячные периоды API, без обещания ровно 60 суток.
- Коды SMS проверяются на сервере и отправляются в чат. Приватные ссылки приёма клиентам не показываются.
- Автоотмены аренды нет в API. Неопределённые покупки и продления разбираются в админке с аудитом.
- Crypto Pay: счёт в USD, приём TON/USDT. xRocket Legacy: счёт в USDT с учётом 1:1 к USD. Прямой TON: курс Crypto Pay, уникальный комментарий и проверка TON Center.
- Повторное подтверждение не создаёт повторное списание или зачисление. После таймаута платная покупка не повторяется автоматически.

## Вебхуки

В админке откройте **«Вебхуки»** в верхней панели. Укажите публичный HTTPS-адрес, выданный Bothost; при открытии админки через HTTPS он подставится автоматически. Настройки хранятся в БД, новых переменных окружения нет.

1. Включите «Принимать сообщения Telegram через вебхук», сохраните и перезапустите бота на хостинге. Он сам зарегистрирует `/webhooks/telegram` с отдельным секретом проверки. До перезапуска режим не меняется. Снимите переключатель и перезапустите, чтобы вернуть polling; накопленные обновления не удаляются. Для локальной проверки оставляйте polling.
2. В настройках приложения Crypto Pay → Webhooks вставьте адрес `/webhooks/cryptopay`, показанный админкой. Подпись проверяется по существующему `CRYPTOPAY_TOKEN`.
3. В настройках приложения xRocket **Legacy** вставьте `/webhooks/xrocket`. Проверяется `Rocket-Pay-Signature` по существующему `XROCKET_TOKEN`; версия приложения не переключается. Формат события Legacy не интерпретируется: подписанное событие запускает проверку ваших счетов через REST API. Схема Current с отдельным webhook secret этой версией не поддерживается.

Платёжные обработчики отвечают после сохранения события в SQLite. Очередь переживает перезапуск, повторные доставки не создают повторных зачислений. Worker проверяет сумму, валюту и принадлежность счёта через API провайдера; после временной ошибки повторяет обработку с задержкой. Опрос платежей остаётся страховкой пропущенных событий. В админке показано число событий, требующих проверки после повторных ошибок.

Для SMS в переданной OpenAPI api.cc нет callback-метода — остаётся опрос раз в 15 секунд. Для прямого TON используется REST TON Center: его Streaming API даёт SSE/WebSocket, отдельный вебхук этим подключением не настраивается. Приход платежей через новые обработчики проверяется тестами; реальную доставку нужно проверить после публикации HTTPS-домена и настройки кабинетов провайдеров.

Документация: [Telegram](https://core.telegram.org/bots/api#setwebhook), [xRocket Legacy signatures](https://docs.xrocket.exchange/api/pay/migration-legacy), [TON Center APIs](https://toncenter.com/).

## Локальный запуск

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
# Если .env ещё нет — скопируйте .env.example и заполните ключи.
.venv/Scripts/python.exe main.py
```

На Windows данные находятся в `data/` проекта. Без `BOT_TOKEN` запускаются только админка и worker. Адрес: http://127.0.0.1:8000. Пароль — `data/admin-access.txt`; ранее заданный вручную пароль сохраняется. Проверка хранилища без Telegram: `python main.py --check`.

## Обычный VPS

[Инструкция](deploy/INSTALL.md). Теперь используется один сервис `app` и постоянный SQLite-том. Явно заданный старый `DATABASE_URL` для внешнего PostgreSQL поддерживается, но для Bothost не нужен. PostgreSQL автоматически в SQLite не конвертируется.

Для резервной копии работающей базы используйте SQLite backup API, а не копирование одного `.db` при активном WAL. Сохраняйте и файлы доступа к админке. Не запускайте несколько копий одного Telegram-бота одновременно.

[Отчёт об исправлениях](docs/REVIEW.md). Реальная покупка проверена локально. Коды SMS бот получает на сервере и отправляет в чат автоматически, ссылки приёма клиенту не показываются. Платежи и запуск на вашем Bothost ещё требуют проверки с вашими аккаунтами. Основной проверенный путь хранения — SQLite.
