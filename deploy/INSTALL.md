# Самостоятельная установка SMENA

Нужен Linux-сервер с Python 3 и [Docker Engine + Compose v2](https://docs.docker.com/engine/install/). Домен необязателен. Приложение на сервере использует PostgreSQL; локальная SQLite-база из демо не переносится автоматически.

## 1. Перенос проекта

На своём компьютере:

```sh
scp smena-server.zip USER@SERVER:~/
```

На сервере:

```sh
unzip smena-server.zip -d smena
cd smena
python3 deploy/setup.py
nano .env
```

Мастер спросит домен (можно оставить пустым) и новый пароль админки. Сам создаст случайный пароль PostgreSQL и строку подключения, сохранит только хеш пароля админки. Если `.env` уже есть, мастер остановится, сохранив его содержимое.

Добавьте в `.env`:

- `BOT_TOKEN` — токен вашего Telegram-бота.
- `APICC_API_KEY` — ключ api.cc.
- `APICC_USD_RATE` — сколько USD стоит единица валюты api.cc. `1` ставьте только после подтверждения, что цены в USD или что вы принимаете курс USDT/USD 1:1.
- `CRYPTOPAY_TOKEN` — Crypto Pay; также нужен для курса TON/USD.
- `XROCKET_TOKEN` — ключ **Legacy API** xRocket.
- `TONCENTER_API_KEY` и `TON_WALLET` — для прямых пополнений в TON.
- `SUPPORT_URL` — ссылка на вашу поддержку.

Ненужные способы оплаты можно оставить без ключей. Мастер уже выставляет mainnet-адреса платёжных API. Пароль PostgreSQL и соответствующий `DATABASE_URL` менять после первого запуска без отдельной смены пароля в БД нельзя.

## 2. Запуск

```sh
bash deploy/manage.sh start
```

Скрипт собирает приложение, проверяет обязательные настройки, ждёт готовности PostgreSQL, применяет миграции и запускает админку, бота и worker. Работать с Docker нужно от пользователя, у которого есть соответствующие права.

**Если домена нет:** на своём компьютере откройте терминал и оставьте работающим туннель:

```sh
ssh -N -L 8000:127.0.0.1:8000 USER@SERVER
```

Откройте <http://127.0.0.1:8000> на своём компьютере. В этом режиме `ADMIN_ACCESS_MODE=ssh_tunnel`, `COOKIE_SECURE=false`, а серверный порт 8000 привязан только к localhost. Передача между компьютером и сервером идёт внутри SSH-туннеля. Снаружи открывать порт 8000 не нужно. Telegram-бот работает без домена через polling.

**Если домен указан:** заранее направьте его DNS A-запись на IP сервера. Если есть AAAA-запись, она тоже должна вести на этот сервер. Порты 80 и 443 должны быть доступны и свободны. Скрипт добавит Caddy; админка будет по `https://ВАШ_ДОМЕН`. В этом режиме `COOKIE_SECURE=true`. Если уже установлен другой reverse proxy, используйте его вместо Caddy: адрес приложения на сервере `127.0.0.1:8000`.

При смене режима вручную согласуйте `ADMIN_DOMAIN`, `ADMIN_ACCESS_MODE` и `COOKIE_SECURE`, затем повторите запуск. Не оставляйте публичную HTTP-админку с режимом SSH-туннеля.

В админке: «Каталог и цены» → импорт из api.cc → категории → настройка цен → включение нужных товаров. Новые товары выключены по умолчанию. Продажи не стоит открывать пользователям до контрольной проверки покупки, продления и каждого выбранного способа оплаты.

Новые номера всегда покупаются с фильтром «Більше 60 днів» (`expiry=5`; OpenAPI описывает его как 60–80 дней). Включить товар без наличия номеров по этому фильтру не получится. Перед самой покупкой наличие проверяется повторно. Продление существующей аренды по-прежнему задаётся стандартными месяцами поставщика, а не этим фильтром.

### Домен выдали после установки

Когда домен будет готов, направьте DNS на сервер и выполните в каталоге проекта:

```sh
python3 deploy/domain.py admin.example.com
bash deploy/manage.sh start
```

Первая команда сохранит копию `.env` в `backups` и изменит только настройки домена, режима доступа и secure cookie. Ключи и пароль базы сохранятся. Вторая перезапустит приложение и подключит Caddy. После выпуска сертификата входите по `https://admin.example.com`; SSH-туннель можно закрыть. Если хостинг уже выдаёт домен с настроенным HTTPS reverse proxy, направьте его на `127.0.0.1:8000` и не запускайте второй proxy на занятых портах — используйте основной `compose.yaml` с настройками `ADMIN_ACCESS_MODE=https`, `COOKIE_SECURE=true`.

## 3. Обновление

Загрузите новые исходники поверх старых, сохранив серверный `.env` и каталог `backups`. Затем:

```sh
bash deploy/manage.sh update
```

Сначала собирается новая версия и создаётся резервная копия БД, затем останавливаются процессы приложения и применяются миграции. При ошибке миграции запуск прерывается — изучите ошибку до повторного запуска. PostgreSQL остаётся запущенным.

## 4. Обслуживание

```sh
bash deploy/manage.sh status
bash deploy/manage.sh logs
bash deploy/manage.sh backup
docker compose exec admin python -m app.cli check-ledger
```

Копии сохраняются в `backups/*.dump`. Копируйте их вне сервера. Для восстановления сначала проверьте копию в отдельной тестовой БД; восстановление поверх действующей базы требует отдельной процедуры и остановки приложения.

Обычная остановка:

```sh
docker compose stop bot worker admin
```

Не используйте `docker compose down -v`: параметр `-v` удаляет том PostgreSQL с данными.

## Что уже проверено

Автоматизированные проверки логики баланса, платежей, поставщика и конфигурации проходят локально. Docker и PostgreSQL в текущем окружении разработки не запускались. Реальные платные операции ещё требуют проверки с вашими аккаунтами. SMS пока доступны по персональной ссылке приёма; для текста SMS непосредственно в боте нужен формат ответа `/api/record`.

Используемые механизмы: [порядок запуска Docker Compose](https://docs.docker.com/compose/how-tos/startup-order/), [reverse proxy Caddy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).
