# Установка вне Bothost

На Bothost используйте Dockerfile и ключи из `.env.example`: база и все службы запускаются автоматически. Дополнительные переменные базы не нужны. Ниже — установка на обычный Linux VPS.

Нужны Python 3 и Docker Compose:

```sh
python3 deploy/setup.py
# Заполните токены в .env
bash deploy/manage.sh start
```

Мастер спросит домен (можно оставить пустым) и пароль администратора. Настройки базы не нужны: SQLite хранится в постоянном Docker-томе `/app/data`. Миграции применяются автоматически. Один сервис `app` заменяет старые отдельные службы `admin`, `bot`, `worker` и PostgreSQL.

Без домена откройте туннель на своём компьютере:

```sh
ssh -N -L 8000:127.0.0.1:8000 USER@SERVER
```

Затем перейдите на http://127.0.0.1:8000. Для домена DNS должен вести на сервер, порты 80/443 должны быть доступны и свободны.

Если домен выдан после установки:

```sh
python3 deploy/domain.py admin.example.com
bash deploy/manage.sh start
```

На Bothost эти команды не нужны — HTTPS предоставляет хостинг.

## Обновление и копии

```sh
bash deploy/manage.sh update
bash deploy/manage.sh backup
bash deploy/manage.sh status
bash deploy/manage.sh logs
docker compose exec app python -m app.cli check-ledger
```

`update` сначала сохраняет согласованную копию SQLite, затем пересоздаёт контейнер. Копии находятся в `backups`. Не удаляйте том `smena_data` с данными.

## Если уже использовали PostgreSQL

Внешний `DATABASE_URL` поддерживается. PostgreSQL автоматически в SQLite не конвертируется. Сохраняйте прежний контейнер и том PostgreSQL до отдельного проверенного переноса. Новый Compose и скрипт рассчитаны на свежую установку или уже используемую SQLite.

## Каталог

«Каталог и цены» → «Валюта поставщика» → фактическая валюта api.cc → импорт → установка цен → включение товаров. Фильтр новых номеров — «Більше 60 днів» (`expiry=5`). Продление — месячными периодами API.

Контрольные реальные операции и выпуск HTTPS-сертификата ещё нужно проверить на вашем сервере.
